## Executive assessment

The previous version of this review is superseded: its count of four unavailable advisory records and many unverified findings was based on querying CVE IDs that OSV did not serve directly. Resolving their GHSA aliases supplied authoritative PyPI ranges. Of the 148 distinct IDs in the original 35-package scan, 147 are applicable to the locked version and one (`PYSEC-2025-194`, torch) is outside its recorded PyPI range. The additional `GHSA-7hp6-4w63-5g45` LiteLLM record is verified through the GitHub advisory and its CVE alias. No original scan match remains unverified after alias resolution. This establishes affected versions, not runtime reachability or exploitability.

The two LiteLLM findings remain applicable to locked `litellm==1.93.0`. GitHub rates GHSA-7hp6-4w63-5g45 Critical (CVSS 9.9); its described escalation/RCE requires the affected LiteLLM Proxy and an authenticated internal user. Harbor's supported deployment does not operate Proxy; source inspection found client usage and no Proxy startup. This is a release-profile boundary, not a package fix, and repository inspection cannot prove what an external operator deploys. Findings for optional and development packages remain applicable if those package paths are installed, but those profiles are unsupported for this release.

The pinned candidate resolver produced a coherent default + dev candidate resolution for Python 3.12/3.13 with no source edits; a full all-extras refresh is not currently coherent. `transformers==5.10.0` conflicts with Harbor's `tinker` extra cap `<=5.5.4`. `wheel>=0.46.2` conflicts with locked `skypilot-nightly==1.0.0.dev20250515` (`wheel<0.46.0`). A checked current Skypilot nightly has `wheel>=0.46.3` but `click<8.2`, conflicting with the Hugging Face Hub requirement `click>=8.4.2`. Do not force either optional conflict into a lock refresh without maintainer decisions.

## Method, evidence and confidence

- Lock versions and dependency paths were read from `uv.lock`; root constraints, extras and groups from `pyproject.toml` and workspace package metadata.
- OSV records were retrieved on 2026-10-24. Records were deduplicated by canonical ID/aliases. CVE lookups returning no record were followed through their GHSA aliases and matching OSV PyPI ecosystem entries. `GHSA-7hp6-4w63-5g45` was separately checked against [GitHub Security Advisories](https://github.com/BerriAI/litellm/security/advisories/GHSA-7hp6-4w63-5g45) and [CVE-2026-114612](https://osv.dev/vulnerability/CVE-2026-114612).
- Fixed candidates below are the lowest reviewed versions that cover all confirmed PyPI ranges unless noted. They are candidates, not authorized changes. OSV affected/fixed event boundaries are authoritative for this check; each package's canonical advisory IDs and aliases are in the appendix.
- PyPI JSON release metadata confirmed the proposed releases exist and their `Requires-Python` includes 3.12, 3.13 and 3.14. Candidate wheel availability was separately inspected. The binary-only dry run succeeded on this Windows x64 / CPython 3.13 environment for the proposed candidates and required companions. Some platform-wheel gaps are called out below; an sdist existing does not guarantee buildability.
- `uv pip compile` succeeded for the candidate default + dev resolution on Python 3.12 and 3.13. A Python 3.14 universal resolution attempt timed out while fetching `psutil` metadata, so 3.14 resolver success remains unverified. The project declares `>=3.12` without an upper bound; compatibility beyond tested 3.14 is unknown.
- Confidence: **High** for version-range applicability and PyPI release existence; **High** for stated root constraints/solver conflicts; **Medium** for inferred dependency paths and proposed compatibility risk (path depends on selected extras); **Unknown** for whether deployments expose optional services such as LiteLLM Proxy.
